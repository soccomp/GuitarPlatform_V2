# AI 吉他陪练老师 v0.1 方案

编写日期：2026-05-03  
编写人：Codex

## 1. 目标

本方案不是新做一个独立系统，而是在现有吉他学习平台内部新增一层“AI 陪练”能力。

第一版目标非常明确：

- 集成到现有 `歌曲练习` 模块
- 允许用户录制一段自己的演奏
- 基于当前歌曲片段、伴奏与节拍信息分析节奏稳定性
- 返回接近真人老师的简短练习反馈

第一版重点不做：

- 左右手动作视觉识别
- 拨弦方向自动识别
- 复杂音高/和弦精确识别
- 边弹边语音打断式实时指导

## 2. 完成后的使用方式

用户在现有平台里的使用方式会是：

1. 打开 `歌曲练习`
2. 选择歌曲、版本和练习段落
3. 使用现有 A/B 和速度控制设定当前练习区间
4. 点击 `开始练习分析`
5. 跟着伴奏演奏一遍
6. 点击 `结束并分析`
7. 平台展示：
   - 节奏稳定性评分
   - 重点不稳小节
   - 抢拍 / 拖拍位置
   - 建议练习速度
   - 老师式点评

理想体验不是“系统测了个数据”，而是“老师告诉你下一步该怎么练”。

## 3. 产品形态

### 3.1 集成位置

第一版仅集成在现有 `歌曲练习` 页面。

建议新增一个独立卡片：

- `AI 陪练`

卡片内包含：

- `开始练习分析`
- `停止并生成反馈`
- 当前录音状态
- 最近一次分析结果
- 老师建议

### 3.2 返回结果示例

  "tempo_mode": "0.75x",
  "stability_score": 78,

## 4. 三端分工

### 4.1 MacBook + openclaw

负责前台交互：

- 打开吉他学习平台
- 选择当前歌曲与片段
- 录音或录像
- 上传分析请求
- 展示分析结果

### 4.2 4080 Windows 笔记本 + Ollama

负责后台重任务：

- 接收录音数据
- 执行节奏分析
- 未来执行更复杂的音频/视频识别
- 调用 Ollama 生成老师式反馈

### 4.3 吉他学习平台

负责业务中枢：

- 保存当前练习上下文
- 保存分析记录
- 将分析结果和当前歌曲版本关联
- 展示问题片段与练习建议

## 5. 技术架构

### 5.1 平台侧

平台侧新增：

- 录音能力
- AI 陪练卡片
- 提交分析请求接口
- 展示返回结果的 UI

建议新增前端流程：

1. `开始练习分析`
2. 浏览器录音
3. `停止并生成反馈`
4. 上传音频 + 当前歌曲上下文
5. 展示结果

### 5.2 分析服务侧

建议在 4080 笔记本上新建一个独立分析服务，例如：

- `POST /api/coach/analyze-rhythm`

输入：

- 录音文件
- 当前歌曲 ID
- 当前版本
- 当前段落
- 当前速度
- 可选：伴奏参考

输出：

- 节奏稳定性评分
- 问题片段列表
- 建议速度
- 老师式反馈

### 5.3 识别方式

第一版建议只做音频节奏分析。

可用路径：

- 录音起音点检测
- 与目标节拍 / 伴奏时间轴对齐
- 估算拍点偏差
- 判断抢拍 / 拖拍 / 稳定性

这一版不追求“完整乐谱级别识别”，只追求：

- 有用
- 快速
- 练琴时真能帮到人

## 6. 老师式反馈原则

系统返回内容不能只是技术结果。

不推荐：

- “第 4 小节偏差 230ms”

推荐：

- “第 4 小节进入时总是略慢”
- “你的节奏框架已经有了，但切分音位置不稳”
- “先不要提速，建议继续用 0.75x 练第 3 到第 5 小节”

也就是说，AI 的角色不是“检测器”，而是“教学解释器”。

## 7. 迭代顺序

### v0.1

- 歌曲练习页新增 AI 陪练入口
- 录音并上传
- 节奏分析
- 返回老师式反馈

### v0.2

- 记录历史练习结果
- 对比上一次表现
- 生成更稳定的练习建议

### v0.3

- 引入音高 / 单音准确率识别
- 识别明显错音或漏音

### v0.4

- 引入右手视频分析
- 识别拨弦路线与动作幅度

## 8. 开发任务拆分建议

建议按以下 Issue 拆分：

1. 平台前端：AI 陪练卡片与录音交互
2. 后端接口：提交练习分析请求
3. Windows 4080 分析服务：节奏分析 API
4. Ollama 提示词：老师式反馈生成
5. 练习结果存档与历史记录

## 9. 风险与边界

当前第一版的主要风险：

- 录音环境噪声
- 吉他原声与伴奏混音后节拍识别难度上升
- 不同歌曲片段节奏复杂度差异大
- 用户希望“像老师”，但模型只能建立在检测结果足够准的前提上

因此第一版的目标不是完美，而是：

- 能可靠发现主要节奏问题
- 能输出可执行的练习建议

## 10. 结论

AI 吉他陪练老师不应该脱离现有平台单独存在。

最合理的形态是：

- 平台继续承担学习和练习工作台角色
- MacBook 作为前台入口
- 4080 笔记本作为后台 AI 引擎
- AI 层在现有练琴流程里提供节奏分析与老师式反馈

这会让平台从“资料管理 + 播放练习工具”升级为“真正会指导你练琴的平台”。
